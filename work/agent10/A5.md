# A5 — typed body streams (URL / markup / prose)

**Killed as Class A.** Splitting article bodies into URL / wiki-markup / prose
and concatenating those streams **loses** to the mixed file under zlib9 and
lzma6. PHDA9-style extract-to-tail also loses. Homogeneity exists (shuffle
hurts) but mixing is already the better layout for a generic compressor, and
fxcm already has HTLINK / template / table contexts.

Not a 3 MB `cmp`. Not A1. Script: `a5_enwik8.py`. Raw numbers: `a5_enwik8.json`.
enwik8 MD5 `a1fa5ffddb56f4953e226637dabbb36a`.

scheme+host extra is 599 KB raw — not megabytes after DIC (89.5% of URL
letters already in `english.dic`).

| in-order type tags + payload | — | −69,850 | −52,124 |
| live concat vs span-shuffle (same bytes, order destroyed) | −5,841,601 | −138,911 | −48,676 |

Shuffle losing means **order inside a type is informative**. Concatenating
still loses to **leaving types interleaved** in dump order. The type-RLE map
is 3.5 MB raw / 1.78 MB zlib on enwik8 — it does not pay for itself.

One small leftover: on a WRT-proxy (letters vs rest) the 3 MB slice,
typed concat **beats** mixed by **18,966** zlib bytes. Non-letter residue
typed concat: **+16,323** zlib. Both are tens of KB on 3 MB → not an
enwik9 megabyte after DIC+fxcm overlap. Class C.
