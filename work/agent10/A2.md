## What regime 1 actually was (public cmix-lex)

Source: [blahem/cmix-lex](https://github.com/blahem/cmix-lex) `changes.md` + `src/r1_reorder_transform.cpp` (fetched, not vendored).

After PHDA9 + WRT the ready stream is **586,459,321** B. The last **45,332,670** B is a line-oriented metadata tail at offset **541,126,651**:

| slice | offset into tail | size |
|---|---:|---:|
| regime 0 | 0 | 13,599,801 |
| regime 1 | 13,599,801 | 16,773,087 |
| regime 2 | 30,372,888 | 14,959,782 |

`payload_lex` **only reorders regime 1**. Regime 0 and 2 stay byte-for-byte.

Regime 1 is **243,425** blocks (one per PHDA9 article), ~69 B each after WRT. A block is an exact `D99` line (`0xDF 0x99 'N'`), then a `D86a` line (`0xDF 0x86 'N'` + decimal), then payload lines. Sort key = payload after those two lines. Inverse is `R1ORD3`: predict original order from visible D86a, store the residual as Lehmer ranks (side **679,489** B, cmix wrote **346,948** B on that EOF region).

PHDA9 (`phda9_preprocess.h` `encode_txt_wit`) does **not** extract infoboxes, categories, or wikilinks. It packs **revision headers** (delta IDs, packed timestamps, stripped contributor XML) and a **lang** stream (`henttail`). Those blobs are concatenated after the transformed bodies and become the post-WRT tail. So:

- **Regime 1 ≈ contributor / header payloads** (the thing they lex-sorted).
- **Regime 0 ≈ packed ID/timestamp/ns numeric header** (delta-coded; lex would fight the delta).
- **Regime 2 ≈ lang / interwiki stream** (~15 MB; leftover of the *existing* tail).

A “second region” is therefore either **lex regime 2** (or 0), or a **new extract from the main 541 MB body** (infobox / category / link-list tables). It is not another 3 MB DIC pointer.

Hardcoded sizes: `ReorderEncodedTailFile` refuses any stream that is not exactly `541126651+45332670`. Prefix A/Bs must patch offsets or dump the tail without calling this function.
